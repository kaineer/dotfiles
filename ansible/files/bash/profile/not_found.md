# not_found

 Да, это именно то, что вы ищете. В Bash для этих целей существует встроенная функция-обработчик — `command_not_found_handle`.
 
 Когда Bash не может найти команду, он вызывает эту функцию, если она определена. В неё передаются **все** аргументы исходной команды: первый аргумент (`$1`) — это имя команды, которую вы пытались вызвать, а остальные (`$2`, `$3`, ...) — её аргументы.
 
 ### Как это работает
 
 Согласно документации, после того как Bash проверит функции, встроенные команды и переменные `PATH`, он ищет функцию с именем `command_not_found_handle`. Если она существует, он вызывает её в отдельном окружении, передавая исходную команду и её аргументы. Код возврата этой функции становится кодом возврата оболочки.
 
 ### Пример реализации
 
 Вот как можно перехватить любую ненайденную команду, например `foooo` с аргументами `--bar`:
 
 ```bash
 command_not_found_handle() {
     # $1 - имя команды (например, "foooo")
     # $@ - все аргументы, включая имя команды ("foooo --bar")
     
     echo "Перехвачено: команда '$1' не найдена."
     echo "Все аргументы: $@"
     
     # Возвращаем 127, как это делает Bash по умолчанию,
     # если мы не можем обработать команду.
     return 127
 }
 ```
 
 Если теперь ввести `foooo --bar`, функция получит `$1` = `foooo` и все аргументы в `$@`. Вместо стандартного сообщения об ошибке выполнится ваш код.
 
 ### Важные детали
 
 - **Код возврата 127**: Если ваш обработчик не может что-то сделать с командой, хорошей практикой является возврат кода `127`. Этот код в Unix-подобных системах означает «команда не найдена». Bash сам использует этот код, если обработчик не определён.
 - **Встроенный обработчик в дистрибутивах**: Многие дистрибутивы Linux (например, Ubuntu) уже определяют эту функцию в файле `/etc/bash.bashrc`, чтобы предлагать пользователю установить пакет, если введена несуществующая команда.
 - **Где определять**: Вы можете добавить эту функцию в свой `~/.bashrc`, чтобы она переопределила системную или добавила свою логику.
